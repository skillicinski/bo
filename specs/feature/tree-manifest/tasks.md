# Tasks: Tree Manifest (3a)

Each task is one focused session. Each follows test-first authoring within itself: tests written and observed-red first, then implementation until green. Each task ends with `cargo test` passing, ready to commit.

## Phase 1: Foundation

- [x] **T1.1 — Tree manifest path helpers.** Write tests in `src/tests/domain_tree_tests.rs` covering: `Tree::manifest_path()` returns `{output_dir}/.bo/manifest.json`; free helper `manifest_path(tree_dir)` returns the same path from a bare `&Path`. Implement in `src/domain/tree.rs` mirroring the existing `index_path`/`state_path` shape. Done when: tests pass; no other code touches these helpers yet.

- [x] **T1.2 — Manifest types + atomic read/write.** Write tests in `src/tests/domain_manifest_tests.rs` covering: serde round-trip of `Manifest` with empty leaves/branches; round-trip with one leaf and one branch including all fields (`created_at`, `updated_at`, `stale`, `leaves`); `manifest::write` produces pretty-printed JSON; `manifest::write` uses `rename(tmp, final)` as the final operation and does not leak `*.tmp` files on the success path; `manifest::write` invokes `debug_assert!` when leaf or branch slugs collide (verify in debug build only); `manifest::read` returns a typed `Parse` error on invalid JSON; `manifest::read` returns `TreeNotInitialized` when the file is absent **and** no secondary store exists. Implement `src/domain/manifest.rs`: `Manifest`, `TreeMeta`, `LeafRecord`, `BranchRecord` per `data-model.md` (note `BranchRecord.created_at` and `BranchRecord.updated_at` — not `compiled_at`); `ManifestError { Io, Parse, TreeNotInitialized }` with `Display` + `From<io::Error>` + `From<serde_json::Error>`; `pub fn read(path)`, `pub fn write(path, &Manifest)`; private `atomic_write(path, &[u8])` that writes `{path}.tmp`, syncs, renames; slug-uniqueness `debug_assert!` inside `write`. Wire into `src/domain/mod.rs`. Reconstruction is **not** in this task — `read` returns `TreeNotInitialized` for missing-file in 1.2; T2.1 inserts the reconstruction branch. Crash-safety beyond filesystem rename atomicity is 3b's domain.

- [ ] **T1.3 — Manifest resolution helpers.** Write tests in `src/tests/domain_manifest_tests.rs` covering each helper against a fixture manifest with 3 leaves (one collected after `tree.last_compiled_at`, two before) and 2 branches (one branch sharing a leaf with another): `leaf_by_slug` hit/miss; `branch_by_slug` hit/miss; `uncompiled_leaves` returns the singleton (the one collected after `last_compiled_at`); `stale_branches` returns empty (no `stale: true` in fixture); `leaves_for_branch` for a known branch and an unknown branch; `branches_for_leaf` returns multiple branches for the shared leaf. Implement `impl Manifest` in `src/domain/manifest.rs`. `uncompiled_leaves` returns leaves where `tree.last_compiled_at` is `None` or `leaf.collected_at > tree.last_compiled_at` (lexicographic comparison on RFC 3339 strings is correct). Done when: all helper tests pass.

## Phase 2: Reconstruction

- [ ] **T2.1 — Reconstruction from secondary store.** Write tests in `src/tests/domain_manifest_tests.rs` covering: build a tempdir with `index.jsonl` (3 entries) + matching leaf `.md` files with frontmatter + `branches/` containing 2 branch `.md` files with `leaves` and `created_at`/`updated_at` frontmatter; call `manifest::read` on the missing manifest path; assert the returned `Manifest` reflects all leaves, all branches, correct cross-references, `tree.last_compiled_at = max(BranchRecord.updated_at)`, and `tree.name`/`tree.created_at` from the existing tree config (with documented fallbacks: dir basename for missing name, `Utc::now()` + stderr warning for missing created_at); assert the manifest is now written to disk; assert a stderr warning was emitted (`manifest missing; reconstructed from secondary store`); assert that a **corrupt** (invalid JSON) `manifest.json` surfaces a `Parse` error and does NOT trigger reconstruction. Implement `fn reconstruct_from_secondary(tree: &Tree) -> Result<Manifest, ManifestError>` as a private helper in `manifest.rs`; modify `manifest::read` so the missing-file branch invokes reconstruction, persists the result, prints the warning, and returns it; the parse-error branch propagates unchanged. Mark the function with a comment: `// Removed in 3b: secondary store is gone, manifest becomes unrecoverable.` Done when: all reconstruction tests pass; existing T1.2 tests for `TreeNotInitialized` and `Parse` errors still pass.

## Phase 4: Mutating writes (manifest as primary)

- [ ] **T4.1 — `bo seed` writes empty manifest.** Extend tests in `src/tests/cli_seed_tests.rs`: after `seed`, `manifest.json` exists at `.bo/manifest.json`; manifest deserializes successfully; `tree.name` matches the seeded name; `tree.created_at` equals the existing seed timestamp from config; `last_compiled_at` is `None`; `leaves` and `branches` are empty. Modify `src/cli/seed.rs` to call `manifest::write` after the existing seed work. Done when: new seed assertions pass; existing seed tests unaffected.

- [ ] **T4.2 — `bo collect` dual-writes.** Extend tests in `src/tests/cli_collect_tests.rs`: after a successful collect, the new `LeafRecord` is present in `manifest.json` with correct slug/file/title/url/collected_at/summary; `manifest.leaves` count matches `index.jsonl` line count after a sequence of 3 collects (parity); secondary `index.jsonl` write still occurs. Modify `src/cli/collect.rs`: after the leaf `.md` is written, call `manifest::write` first (manifest is primary), then `index::append_entry` (secondary). Both errors propagate; if manifest write fails the command aborts with the manifest error. **Dedup remains on `index.jsonl` for now** — that's T5.6. Done when: dual-write tests pass; parity assertion green; existing collect tests unaffected.

- [ ] **T4.3 — `bo compile` dual-writes; frontmatter field rename.** Extend tests in `src/tests/cli_compile_tests.rs`: after a successful compile against a fixture tree with N≥2 leaves, `manifest.branches` contains M≥1 records, each with correct slug/file/title and a non-empty `leaves` vector matching the corresponding branch `.md` frontmatter; `BranchRecord.created_at` equals `run_timestamp` on first compile and is **preserved unchanged** across a second compile of the same tree (recompile sets `updated_at` to the new run_timestamp but leaves `created_at` alone); `tree.last_compiled_at` equals `run_timestamp` after each compile; `state.json` is still updated (parity); branch `.md` frontmatter uses `created_at` and `updated_at` (not `compiled_at`). Modify `src/cli/compile.rs`: materialize a `Vec<BranchRecord>` from the validated LLM response as an explicit intermediate; for each emitted branch, look up the existing entry in the previously-loaded manifest by slug — if present, reuse its `created_at`; otherwise set `created_at = run_timestamp`. Always set `updated_at = run_timestamp`. Build a new `Manifest` value with replaced `branches` and updated `tree.last_compiled_at = run_timestamp`. Call `manifest::write` first, then write branch `.md` files via `branch::write` (secondary), then update `state.json` (secondary). Update `src/domain/branch.rs`: rename `branch::write`'s `compiled_at` parameter and frontmatter key to `created_at` (`updated_at` stays); rename `branch::read_compiled_at` to `branch::read_created_at`. `BranchRecord.stale` is always `false` in 3a. Done when: compile dual-write tests pass; existing compile tests adjusted to the new frontmatter field name; preservation test passes; status's existing `last_compiled_at` derivation continues to work (it still scans frontmatter via `read_created_at` until T5.5 migrates it to read from manifest).

- [ ] **T5.5 — `bo status` reads from manifest.** Extend tests in `src/tests/cli_status_tests.rs` covering: `status` derives leaf count, branch count, uncompiled leaves, and `last_compiled_at` from the manifest; remove any reliance on `state.json` reads or `branches/` scanning for these metrics.
