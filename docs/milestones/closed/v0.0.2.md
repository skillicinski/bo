# v0.0.2 Milestone: Compile Grows Up

**Status:** Complete  
**Target:** The compile loop becomes production-grade for growing trees.

## Narrative

v0.0.1 proved the collect→compile→query loop works. v0.0.2 makes compile the intelligent part — incremental, safe, aware of its own state. The tree compounds knowledge sustainably rather than requiring expensive full recompilation.

This is the first release where a visitor sees "this *thinks* about my collection" rather than "this is a script I could write in a weekend."

**npm distribution was pulled forward from v0.1.0 into v0.0.2.** Users can now install bo with `npm install -g @skillicinski/bo` — no Rust toolchain required.

### 2. Compile validation gate

**Goal:** Compile never writes malformed branches. Bad LLM output is caught and rejected before any file mutation.

- [x] Validate structured LLM response shape (expected fields present, correct types)
- [x] Verify all referenced leaf slugs exist in the tree
- [x] Reject empty branch bodies or invented file paths
- [x] Sanity check: diff size is not absurdly large relative to input
- [x] On validation failure: surface errors, write nothing, exit non-zero
- [x] Unit tests: valid response passes, various malformed responses rejected
- [x] Integration test: mock LLM returns bad output → no files written, clear error

**Done when:** A deliberately malformed compile response (missing fields, phantom leaf references, empty bodies) is rejected with no partial writes.

### 3. Manifest as single source of truth

**Goal:** Single source of truth for tree topology with crash-safe mutations. Foundation for incremental compile, dry-run, and future DB migration.

See [ADR-004](../adrs/004.md) for full design rationale and schema.

Split into two stages to keep PR blast radius reviewable.

#### 3a. Manifest reads + dual-write

Introduce `manifest.json` as the canonical read surface. Continue writing `index.jsonl` and `state.json` as a safety net. Pure additive change — no behaviour regressions, no recovery story yet.

- [x] Define `Manifest`, `TreeMeta`, `LeafRecord`, `BranchRecord` types in `src/domain/manifest.rs` (per ADR-004 schema; cross-reference is `BranchRecord.leaves` only)
- [x] `manifest::read()` / `manifest::write()` with atomic rewrite (write tmp + rename)
- [x] Resolution helpers: `leaf_by_slug`, `branch_by_slug`, `uncompiled_leaves`, `stale_branches`, `leaves_for_branch`, `branches_for_leaf` (inverse computed in-memory)
- [x] `bo seed` writes initial empty `manifest.json` alongside existing seed artifacts
- [x] `bo collect` dual-writes: append to `index.jsonl` (legacy) AND update `manifest.leaves`
- [x] `bo compile` dual-writes: update `state.json` (legacy) AND populate `manifest.branches` + `last_compiled_at`
- [x] Switch read paths over to manifest: `bo status`, `bo list`, `bo show`, `bo query`, duplicate-detection in collect
- [x] `bo raze` deletes `manifest.json`
- [x] Unit tests: manifest CRUD, resolution helpers, dual-write parity (index.jsonl and manifest agree)

**Done when:** All read paths consult the manifest. `index.jsonl` and `state.json` are still written but no longer read by any command. Deleting them and running any read command yields identical output.

#### 3b. Cut over writes + write-intent recovery

Remove the legacy writers, add `pending.json`, implement crash-safe stage-then-commit-then-rename, advisory lock.

- [x] Define `PendingOperation`, `OpKind`, `CompileMode`, `PendingWrite` in `src/engine/pending.rs`
- [x] `pending::read()` / `pending::write()` / `pending::clear()` with atomic semantics
- [x] Mutating commands follow stage-then-commit-then-rename ordering: write `pending.json` → stage `*.tmp` → write manifest (commit) → rename tmps → delete pending
- [x] Advisory lock: refuse mutating commands when a live (PID alive, started_at <60s) `pending.json` exists; treat older entries as crashed runs
- [x] Recovery on startup: roll forward if manifest committed (clean up tmps, apply remaining renames/deletes); roll back if not (delete tmps); always delete `pending.json` after
- [x] Crash recovery messaging: one-liner shot back at user/machine; `recovered N changes from interrupted <op>`
- [x] Concurrency refusal: if another bo command PID is touching the tree, exit 2, message: `another bo process is already interacting with <path/to/tree>`
- [x] Remove `index.jsonl` and `state.json` writers; remove `src/engine/state.rs` and the `index_path`/`state_path` helpers from `src/domain/tree.rs`
- [x] Remove `src/domain/index.rs` (or reduce to compatibility-free dead code removal)
- [x] `bo raze` cleans up `pending.json` if present
- [x] Unit tests: pending write/recovery, advisory lock semantics, hash-based roll-forward
- [x] ~~Integration tests: simulate crash mid-collect and mid-compile, verify recovery yields consistent state~~ (deferred — unit tests cover critical paths; revisit if users report recovery bugs)

**Done when:** All tree state lives in `manifest.json`. A killed process mid-mutation leaves a recoverable `pending.json`. `index.jsonl` and `state.json` are gone from the codebase.

### 4. Incremental compile

**Goal:** Default compile processes only new leaves and fits them to existing branch structure. Full recompile is opt-in.

- [x] On `bo compile`: identify leaves with `collected_at > tree.last_compiled_at` (timestamp watermark)
- [x] If no new leaves and no stale branches: report "nothing new to compile", exit 0
- [x] LLM prompt receives: existing branch structure (from manifest) + new leaf summaries/context
- [x] LLM outputs: assignments of new leaves to existing branches, and/or new branch definitions
- [x] Existing non-stale branch prose may be updated only when new leaves are integrated; no delete/rename/merge/split outside `--all`
- [x] `--all` flag: recompile full corpus regardless of watermark and allow full graph rewrite
- [x] Detect deleted leaves referenced by branches and repair/remove stale branches automatically
- [x] Update `tree.last_compiled_at` to compile start-time on successful compile
- [ ] ~~`--dry-run` flag~~: deferred to separate slice (captured in `docs/scratchpad/features-captured.md`)
- [x] `compile_model` config key threaded through (may need different model from query)
- [x] Unit tests: incremental selection logic, stale detection
- [x] Integration tests: collect → compile → collect more → compile again (only new processed)
- [x] (Carried from 3b) Recovery messaging: emit `recovered N changes from interrupted <op>` on successful crash recovery
- [x] ~~(Carried from 3b) Integration tests: simulate crash mid-collect and mid-compile, verify next invocation recovers cleanly~~ (deferred — see 3b)

**Done when:** A 50+ leaf tree with 3 new additions compiles in seconds (touching only new leaves), a manually deleted leaf causes its branch to be flagged stale.

### 6. Query no-answer hardening

**Goal:** When retrieval finds irrelevant content, query reports "no answer" rather than synthesizing from noise.

- [x] Implement retrieval relevance floor (minimum match quality before invoking synthesis)
- [x] Generic-term filtering: very common terms that match many unrelated leaves don't trigger synthesis
- [x] If synthesis runs but produces zero valid citations: treat as not-answered (extend existing zero-citation logic)
- [x] Human output: clear "no relevant sources found" messaging
- [x] JSON output: `insufficient_sources` or `low_relevance` error code
- [x] Unit tests: below-threshold retrieval → no synthesis call

**Done when:** `bo query "quantum chromodynamics"` against a Rust programming tree exits with clear "no answer" rather than attempting synthesis against string-matched noise.

## Success criteria

- A tree with 50+ leaves can `bo compile` in seconds (only processing new leaves), not minutes.
- `bo status` tells you at a glance what's new and uncompiled.
- Compile never writes malformed branches (validation gate catches bad LLM output).
- Query never presents hallucinated answers as grounded (zero-citation = explicit "no answer").
- `bo collect` accepts multiple URL inputs or a `.txt` URL list and reports per-source outcomes.

## Release mechanics

2. Update CHANGELOG.md.
3. Bump version in Cargo.toml to `0.0.2`.
4. Merge, tag `v0.0.2`, push tag → release workflow runs.
